# First hardware run: Arduino Uno (2026-11-04)

The first run of the conformance suite on a physical board. **Board:** a Smraza Uno R3 clone with an ATmega16U2 USB chip (USB `2341:0043`), ATmega328P at 16 MHz with Optiboot. **Host:** macOS, port `/dev/cu.usbmodem1101`.

**Build:** preset `avr-uno-hil`, built from branch `feat/hil-uno` (#58): tiny profile, checked, crash record on, avr-gcc 14.4.0, configuration `dbc519b5c8f2fce5`.

**Programmer:** EmbCC's `embflash --stk500` (EmbCC #172), its first use on hardware: 96 pages written and verified for `test_smoke`.

### The crash record across the watchdog reset

`tools/crashdec` decodes the record the second boot printed and resolves its address to the line of the injected fault:

```
crash record v2 (34 bytes), build 2ef5cf61
  fault      check (class 11), code 0x5eed
  uptime     15 ticks; then reboot
  pc         0x259 (byte address 0x4b2) in crash_record_survives_reset at tests/conformance/test_crash_reset.c:35
```

This also confirms the AVR port's `.init3` watchdog stop (A73) on silicon: after the watchdog reset the part booted once, did not loop, and finished the test.

### Context switch (R-003 T5)

```
bench notify round trip (2 switches): total 405759 cycle-units over 20000 ops; per op x100 = 2028
meta: board arduino_uno, compiler gcc, profile tiny, checked 1, cycle unit hz 250000
```

That is 20.28 units of 4 µs per switch: **about 81 µs, about 1,300 CPU cycles** per notification hand-over plus switch. The build is **checked**, with argument, context and handle checks on every call. The R-003 target is measured on the release build (`footprint_t1` configuration), which has not been run on the board yet. The cycle unit is Timer1's tick (prescaler 64), so the resolution is 4 µs; a logic analyzer measurement can refine it.

## Release and T1 builds

The same board, the same evening, with the same compiler and runner (`EMB_CONF=configs/release.conf` and `configs/footprint-t1.conf`, `EMB_TEST_EMULATOR=hil`):

| Build | Configuration | CTest | Notification round trip, per switch |
|---|---|---|---|
| checked (above) | `dbc519b5c8f2fce5` | 17/17 | 20.28 units: 81.1 µs, about 1,298 cycles |
| release | `7bef7fe0183c9585` | 15/15 | 16.95 units: 67.8 µs, about 1,085 cycles |
| T1 (footprint, release) | `20b21602a3c69026` | 12/12 | 16.60 units: 66.4 µs, about 1,062 cycles |

The release build has no crash record, so no crash images run; T1 has no mutexes, event flags or message queues either.

**How to read the switch figures.** A unit is 4 µs (Timer1 at 16 MHz with prescaler 64); the per-switch figure is the total over 20,000 hand-overs, so it is far finer than one unit. Each hand-over is a notification set, a wake, a switch, and the partner's wait. On the AVR a switch alone saves and restores 32 registers.

**These are not R-003 T5 results.** T5 (200 cycles or less) is defined on an STM32F407 Cortex-M at 168 MHz, measuring a plain yield. These are the first measured figures on the 8-bit part, a reference for the AVR port, and the checked build's safety checks cost about 210 cycles per hand-over.
