# Clang images on the Uno and the ESP32 (2026-11-06)

The kernel built by Clang ran its conformance suite on both physical boards on hand ([A100](../specs/AMENDMENTS-M3.md), ADR-053). Every image passed that fits the part. The Cortex-M and RISC-V Clang builds of the same change have no board here yet; they ran under QEMU only.

**Commit:** `2661b89`, from a clean tree (branch `feat/clang-cross`), for all six runs below.

**Boards:**
- the Arduino Uno R3 clone of the [earlier runs](hil-uno-2026-11-05.md), on `/dev/cu.usbmodem11101`, flashed by `embflash --stk500`;
- the ESP-WROOM-32 board of the [port's runs](hil-esp32-port-2026-11-05.md), on `/dev/cu.usbserial-0001`, CPU at 160 MHz, flashed by `embflash --esp`.

The Uno ran fewer images than its avr-gcc suite, because Clang's AVR code does not fit them all:
- **Size:** Clang's AVR code is about 28% larger than avr-gcc's at `-Os`. The base kernel archive is 21,839 bytes of text against 17,029.
- **What doesn't fit:** `test_mutex` (both builds) and `test_msgq` (checked) overflow the ATmega328P's 32,256 bytes of application flash, by 3,110, 2,748 and 888 bytes. `-Oz` shrinks the release kernel to 15,590 bytes, but `test_mutex` still overflows, by 408.
- **Footprint gate:** the T1 gate measures the avr-gcc build.

## Speed against GCC at the same commit

`bench_compare` from the same two release runs, beside the GCC build of the same commit and configuration, run on the same board in the same session.

| Uno, µs per operation | avr-gcc 14.4.0 | Clang 23.1.5 |
|---|---|---|
| `notify_handover` | 61.3 | 56.3 (−8%) |
| `sem_handover` | 60.5 | 56.5 (−7%) |
| `sem_give_take` | 22.1 | 21.4 (−3%) |
| `isr_wake` | 103.2 | 96.2 (−7%) |
| `bench_compare` image text | 9,240 B | 10,732 B (+16%) |

| ESP32, CPU cycles per operation | Espressif GCC 16.1.0 | Espressif Clang 22.1.4 |
|---|---|---|
| `notify_handover` | 899 | 1,060 (+18%) |
| `sem_handover` | 909 | 986 (+8%) |
| `sem_give_take` | 206 | 215 (+4%) |
| `isr_wake` | 1,752 | 1,972 (+13%) |

What these show:
- **Uno:** Clang trades flash for speed. It is 3–8% faster than avr-gcc and 16% larger.
- **ESP32:** GCC stays ahead of Clang. Both builds remain well ahead of ESP-IDF's FreeRTOS on the same board ([report](bench-esp32-freertos-2026-11-06.md): 1,535, 1,959, 316 and 3,201 cycles).
- **The kernel change:** these runs include ADR-055 (the running thread stays listed, #85). On the ESP32 it makes the GCC build 7% faster per notification switch and 10% faster per interrupt wake than the #84 figures in that report (969 and 1,951 cycles).
- **Method:** a Uno timing unit is 4 µs (Timer1 at 250 kHz), averaged over thousands of operations. The ESP32 counts CCOUNT cycles. One board and one run each, so these are comparisons, not rankings.

The GCC benchmark runs are kept with the records: `hil-runs/2026-11-06-arduino_uno-gcc-bench/` and `hil-runs/2026-11-06-esp32_devkitc-gcc-bench/`.

## How to repeat

```sh
# Uno: Clang 23 on PATH (Homebrew llvm), avr-gcc for the link
cmake --preset avr-uno-hil -B build/avrc-hil-checked \
  -DCMAKE_TOOLCHAIN_FILE=$PWD/cmake/toolchains/avr-clang.cmake \
  -DEMB_SET=EMB_CRASH_RECORD=y -DEMB_HIL_PORT=/dev/cu.usbmodem11101
cmake --build build/avrc-hil-checked -- -k 0   # test_mutex, test_msgq do not fit
ctest --test-dir build/avrc-hil-checked -E '^(test_mutex|test_msgq)$'

# ESP32: Espressif's clang and ld.lld on PATH
cmake --preset xt-esp32-clang -B build/xtc-hil-checked -DEMB_HIL_PORT=/dev/cu.usbserial-0001
cmake --build build/xtc-hil-checked && ctest --test-dir build/xtc-hil-checked
```

The release builds add `EMB_CHECKED=n` to `EMB_SET`: on the Uno, `-DEMB_SET="EMB_CRASH_RECORD=y;EMB_CHECKED=n"`, which leaves out only `test_mutex`.
