# ESP32: the kernel's Xtensa port on hardware (2026-11-05)

The first runs of the conformance suite on the classic ESP32, with the Xtensa port of [ADR-054](../architecture/06-decision-records.md) and [A95](../specs/AMENDMENTS-M3.md).

- **Board:** the ESP-WROOM-32 development board of the [bring-up probe's run](hil-esp32-2026-11-05.md), an "ESP-32S" DevKitC copy. It has an ESP32-D0WD, 40 MHz crystal, 4 MB flash and a CP2102 USB-serial bridge with auto-reset.
- **Host:** macOS, port `/dev/cu.usbserial-0001`.
- **Flasher:** EmbCC's `embflash --esp` (EmbCC #173), at 460800 baud, verified by MD5.

**Build:** preset `xt-esp32-hil` (board `esp32_devkitc`), at commit `97ca415` with a clean tree (branch `feat/xtensa-port`).
- **Toolchain:** EmbCC 0.0.1-beta with the `embld` of EmbCC #174 (Xtensa linker scripts, D-024).
- **Configuration:** base profile. Checked is configuration `1fc9c964c0006f0f`. Release (`EMB_SET=EMB_CHECKED=n`) is `a6675cd36514cdfd`.
- **CPU:** 40 MHz, as the ROM leaves it.

**Records:** `docs/engineering/hil-runs/2026-11-05-esp32_devkitc-checked/` and `-release/` hold each image's console and record. Each record has the SHA-256 of the ELF and of the `.bin` embflash wrote, the commit, the times and every case line. Each directory's `index.json` sums them (`tools/hil/archive.py`).

## Results

`ctest --test-dir build/xt-esp32-hil`: **24 of 24 passed** in each build, the 21 conformance suites and the three benchmarks.

In the checked build, **157 cases** passed and **74 fault checks** reset the board and were settled on the next boot (A89). The board reset by RTC_CNTL_SW_SYS_RST, which keeps SRAM2 and the framework's record in it. `test_crash_reset` shows the crash record surviving the same reset.

The interrupt stack's high-water mark peaked at 384 of 1024 bytes, in `test_workq`, and was 160–272 bytes elsewhere.

The release build passed 155 cases. A release build turns misuse into returned statuses, so no check resets the board, and `test_isr_stack` runs only the one case that needs no checked build.

## Benchmarks

Counted on CCOUNT, in CPU cycles at 40 MHz. Per operation:

| | checked | release |
|---|---|---|
| `bench_compare` notification hand-over (2 switches) | 2090 | 1761 |
| `bench_compare` semaphore hand-over (2 switches) | 2075 | 1754 |
| `bench_compare` semaphore give and take, no switch | 436 | 411 |
| `bench_compare` interrupt wakes a higher-priority thread | 4211 | 3265 |
| `bench_switch` notification hand-over | 2079 | 1750 |
| `bench_irq` `emb_irq_pend()` to the handler, average (min, max) | 336 (333, 1188) | 326 (325, 811) |

In the interrupt wake, the driver pends FROM_CPU_INTR0 through `emb_irq_pend()`. The handler gives a semaphore, the echo thread at a higher priority preempts at the interrupt's exit, takes it again and blocks.

A scratch image (not filed) measured the parts of a switch in the release build. Each figure is cycles per iteration over 1000:

| | cycles |
|---|---|
| an empty loop iteration | 7 |
| a call and return of an empty function | 8 |
| a lock and unlock | 8.5 |
| a software-interrupt round trip that resumes the same thread | 318 |
| the same, three calls deeper | 479 |
| `emb_thread_yield()` with nothing to switch to | 196 |

Each live frame thus adds about 54 cycles: its spill at the entry, and its refill by a window underflow after the resume. That cost belongs to the windowed ABI. The rest of a hand-over is the kernel's C path. A yield that switches nothing costs 196 cycles, which is EmbCC's code for Xtensa as much as the kernel's.

CI builds the same tree with Espressif's GCC (`xt-esp32-gcc`) and keeps the images. Flashing them on this board will separate the compiler's share from the port's. That run, and FreeRTOS on the same board in cycles, come next.

## Found by the runs

- **The window spill.** The port's entry spills the interrupted thread's windows while a1 still holds its stack pointer. The bring-up interrupt probe that preceded the port moved a1 first. That probe was correct only because its handler was too shallow to overflow the interrupted function's caller.
- **Stack size.** A thread blocked in the kernel with an interrupt frame on top used 528–560 bytes. The samples' 512-byte stacks overflowed their guard at once, so the port's minimum is 768 bytes.
- **Lost lines.** A fault check resets the board right after the first case's `EVIDENCE` line. RTC_CNTL_SW_SYS_RST discarded what UART0's 128-byte FIFO still held, and three records lost their configuration. The port now calls `emb_board_reset_prepare()` before the reset, and this board waits there until the FIFO is empty. The Uno's one-byte transmit buffer never showed it.
- **The flasher's reset.** `embflash --esp` resets the board when it has flashed, so the image starts before the console is open. `run_hil.py` resets the board again once the console is open, and discards what arrived while it held EN low. Twice in 48 flashes the ROM loader missed a block. The runner now flashes once more when that happens; no retry was needed in the filed runs.
