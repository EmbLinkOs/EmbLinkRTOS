# Specification amendments recorded during M2

Corrections found while preparing the M2 primitives, where an accepted specification, requirement or decision record contradicts another or the implemented behavior. Each is applied in the affected document; this page keeps the audit trail. Numbering continues from the [M1 record](AMENDMENTS-M1.md). Decisions about the new M2 primitives themselves are recorded separately, as they are taken.

| # | Document | Amendment | Where in the code |
|---|---|---|---|
| A29 | KRN-TIM-035, SPEC-003 §12 | The requirement's last clause, `EMB_EOVERFLOW` for a `_until` deadline out of the 32-bit profile's range, contradicts A2 and KRN-TIM-022: such a deadline is indistinguishable from a past instant and takes the past-deadline path. The clause is removed; the checked-build timer detections remain. | `kernel/thread/thread.c`, `kernel/sync/*.c`, `kernel/notify/notify.c` |
| A30 | SPEC-004 §9 | A blocking wait from an ISR, with the scheduler locked or inside the caller's critical section returns `EMB_EPERM` in release builds, as SPEC-001 §5.3, SPEC-005, SPEC-006 and SPEC-007 state and `EMBK_API_REQUIRE_CAN_BLOCK` implements; the table's `EMB_EINVAL` was wrong. | `kernel/include/embk/kernel.h` |
| A31 | ADR-027 | A binding costs a thread pointer and a one-bit mask, not a bit index (A23, KRN-NOTIF-012). | `kernel/include/embk/sync.h` |
| A32 | KRN-NOTIF-012 | The verification cited binding cases in `tests/conformance/test_sem.c`, which has none; the existing case is `notify_semaphore_binding_signals_ready_transition` in `tests/conformance/test_notify.c`. | `tests/conformance/test_notify.c` |
| A33 | KRN-NOTIF-009 | The requirement is accepted but only partly implemented: `EMB_EEXIST` for a second bind and dropping a set to a terminated thread exist; `unbind` and target-lifetime rules are M2-03 work. The status now says so. | `kernel/sync/sem.c`, `kernel/notify/notify.c` |
| A34 | A15, SPEC-004 §11 | The table profile drops the per-thread wait generation as well: it is uniprocessor only, and on a uniprocessor the timeout is disarmed in the section that ends the wait, so nothing reads it. The byte holds the binding reference count (A36, ADR-046) and the tiny TCB stays at 32 bytes on AVR. | `kernel/include/embk/kernel.h`, `kernel/wait/wait.c` |
| A35 | SPEC-006 §7, KRN-NOTIF-011, SPEC-015 | There is no separate `bind_signal` event: a binding's signal is the `notify_set` record with the bound object as its third argument, which a direct set leaves zero. Existing trace decoders and archived captures stay valid. | `kernel/notify/notify.c` |
| A36 | SPEC-009 §2, SPEC-006 §3.1 | The binding lives in each ready-state object as an `embk_binding_t`, not in the common object header, so objects that cannot be bound pay nothing for it. | `kernel/include/embk/binding.h` |
| A37 | SPEC-006 §3.1 | `unbind` is `prekernel thread`, like `bind`, so setup and teardown code can run before the kernel starts. | `kernel/sync/sem.c` |
| A38 | SPEC-005 §5.2 | An event waiter's mask lives in `wake_data` until a waker replaces it with the handed-off bits, and its mode in the thread's two bit-wait mode bits (ALL, CLEAR), shared with notification waits; the TCB does not grow, which the tiny profile's 32-byte budget requires. | `kernel/sync/event.c`, `kernel/include/embk/kernel.h` |
| A39 | SPEC-005 §5.2, §8 | `emb_event_wait()` with a zero mask or an unknown mode bit is an argument misuse; `set` and `clear` of zero bits are valid no-ops. | `kernel/sync/event.c` |
| A40 | SPEC-005 §5.1, SPEC-001 §6.4 | Event flags get `emb_event_attr_default()` and `emb_event_unbind_notify()`; like semaphores and mutexes they have no `_DEFINE` macro yet, which stays one cross-type change. | `include/emb/event.h` |
| A41 | SPEC-005 §6 | The mandatory relock of a condition wait defers cancellation (the thread's cancel-disable count is raised around it), so a cancel cannot return the caller without its mutex; it is delivered at the next cancellation point. | `kernel/sync/cond.c` |
| A42 | SPEC-005 §6 | Condition wait results: `EMB_EOWNERDEAD` or a relock failure (`EMB_EDEADLK`, `EMB_EDESTROYED`) wins over the wait's result; a pending cancel or `EMB_NO_WAIT` returns before the mutex is released. `emb_cond_attr_default()` and `emb_cond_attr_t` (name, flags) are defined. | `include/emb/cond.h` |
| A43 | SPEC-007 §2.1, §7 | The ring is named `ring` with its size in `ring_size`, so init can refuse an undersized ring as §7 requires and the field is not confused with the object's own storage argument; `EMB_MSGQ_RING_SIZE()` gives the size. `pool` and `EMB_MSGQ_OWNERSHIP` are omitted until buffer pools exist, and `emb_msgq_attr_default()` and `emb_msgq_unbind_notify()` are added like the other M2 objects. | `include/emb/msgq.h` |
| A44 | SPEC-007 §2.2 | `send_front` takes no timeout: it hands off to a waiting receiver, else writes at the head, else returns `EMB_ETIMEDOUT`, and is not a cancellation point. The receive branch for a sender waiting on an empty ring is unreachable (senders wait only while full, capacity at least 1) and is removed. `peek` on an empty queue returns `EMB_ETIMEDOUT`. | `kernel/ipc/msgq.c` |
| A45 | SPEC-007 §2.1, §9, KRN-IPC-021 | Public counts and sizes are `uint16_t`. With `CONFIG_EMB_IPC_SMALL` the object keeps 8-bit counts, so a capacity above 255 is an argument misuse and `CONFIG_EMB_MSGQ_MAX_ITEM` is limited to 255. | `kernel/include/embk/ipc.h` |
| A46 | SPEC-007 §2.2, KRN-IPC-018 | A receive that refills the freed slot from a waiting sender does not signal the binding: the queue is never observed empty, which is the hand-off rule applied to the send side. | `kernel/ipc/msgq.c` |
| A47 | SPEC-007 §1, §8, SPEC-015 | `send`, `receive`, `send_front` and `peek` are `thread isr` (waits from an ISR are `EMB_FAULT_API_CONTEXT`/`EMB_EPERM`); the `_until` forms are thread-only. The trace records are `EMB_TRACE_MSGQ_SEND` (send and send_front) and `EMB_TRACE_MSGQ_RECEIVE`, with the caller's index, the queue and the status of every outcome (A19); a waiting receiver or sender shows as the partner's wake record and the generic block record. `peek`, `count` and `free` are not traced. | `kernel/ipc/msgq.c`, `include/emb/trace.h` |
