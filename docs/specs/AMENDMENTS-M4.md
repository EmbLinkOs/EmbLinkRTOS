| A127 | SPEC-015 §2, §7, §9, §12 decision 2, OBS-002, OBS-003, OBS-013, OBS-021, 08 Q13 | **Logging, its ring and the console.** **Call sites (§2.1):** a module is defined once with `EMB_LOG_MODULE_DEFINE(name, level)` and declared in its other files with `EMB_LOG_MODULE_DECLARE(name, level)`; §2.1 had only the declaration, which cannot both define the module and serve a module whose calls span files. `EMB_LOG_ERR`, `_WRN`, `_INF` and `_DBG(name, format, ...)` take at most eight arguments, and the compiler checks each format against its arguments as it checks printf's. A call above its file's level for the module, or above `CONFIG_EMB_LOG_LEVEL_MAX`, compiles to nothing; one above the module's run-time level (`emb_log_level_set()`) returns after one comparison. **One record, two backends (§2.3, §2.4, Q13):** every call packs its arguments into the record of §2.3 in the caller, typed by a signature the compiler computes from their C types with C11's `_Generic` (int, long, long long and their unsigned forms, double, string, pointer). The deferred backend (ADR-009) sends the record and the host formats it; the plain-text backend formats the same record on the target, in the log thread. Neither formats in the caller, so a call costs the same in an interrupt with either backend. **Identifiers (§2.2):** a call site's metadata (format, file, line, level, module, signature) is placed in the section `emb_log`, which the generated linker scripts lay at address 0 as a non-allocated (`INFO`) section. Its bytes stay in the ELF for the decoder and never reach the image. §2.2's `NOLOAD` would drop them from the ELF too. The identifier is the metadata's offset in the section plus 8, so identifiers 0 to 7 are the stream's own: 0 synchronization, 1 `dropped(u16 count)`, 2 `start(build_id[20], tick_ns u32)`, the first record in the ring, which says which image the stream comes from and how long a tick is. It is 16 bits when the section is under 64 KiB minus 8, else 32. The target computes the width from the section's bounds, so it is fixed at link time, and the decoder computes it from the ELF's section, with no ELF note. A linker without the script places the section as ordinary data, with the same identifiers. The plain-text backend's metadata is ordinary read-only data, and its record carries the metadata's address. **Timestamp:** the kernel clock's ticks, their low 32 bits, each tick as long as the start record says. §2.3 used the trace clock, which wraps within seconds on a fast part, while logs can be minutes apart. **The ring (§2.3, §2.5, §12 decision 2):** one ring per CPU, a power-of-two array of `CONFIG_EMB_LOG_RING_SIZE` bytes. *Reservation* is a critical section of a bounded number of instructions: it checks the free space, advances the head by the record's size and writes the record's two-byte header (its length, not yet committed). The producer then copies its record with interrupts enabled and *commits* it by setting the header's committed bit, one byte store after a barrier. *Nested producers:* an interrupt that preempts a producer reserves after it, so records keep the order in which they were reserved. *Publication:* the log thread takes records from the tail in order and stops at the first uncommitted one, and the records after it wait, committed or not, until it is committed. *A preempted record* holds back those after it until its producer runs again; meanwhile the ring fills and later records are dropped. Nothing is overwritten and nothing waits. *Overflow:* a record that does not fit is dropped and counted, and the next record that fits is preceded by the `dropped` record, in the same reservation, so the count stands where the loss was. *Consumer progress:* only the log thread advances the tail, inside the same critical section, since a 16-bit store is not atomic on AVR. A record is at most `EMB_LOG_RECORD_MAX` bytes: strings are cut at `CONFIG_EMB_LOG_STR_MAX` and hexdumps at `CONFIG_EMB_LOG_HEXDUMP_MAX`. This replaces §12 decision 2's lock-free ring. Cortex-M0 and AVR have no compare-and-swap for a lock-free reservation, and one design verified on every port is worth more than a second one. The critical section is bounded by constants, which is what OBS-003 asks. The ring does not survive a reset; `emb_log_flush()` writes out what is committed, polled, from any context, and the fault path calls it. **The log thread (§2.4):** a thread of its own (`CONFIG_EMB_LOG_THREAD_PRIORITY`, by default the lowest application priority, and `CONFIG_EMB_LOG_THREAD_STACK`), woken by a semaphore given when a record lands in an empty ring. It is not the system work queue, whose other items a slow console would hold up.
