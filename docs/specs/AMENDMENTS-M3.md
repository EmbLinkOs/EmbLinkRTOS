# Specification amendments recorded during M3

Corrections and implementation decisions made during M3a, where an accepted specification
is narrowed, reordered or made concrete. Each is applied in the affected document, and this
page keeps the audit trail. Numbering continues from the [M2 record](AMENDMENTS-M2.md).

**Status:** proposed with the first hardware generator increment, awaiting the project owner's review.

| # | Document | Amendment | Where in the code |
|---|---|---|---|
| A66 | SPEC-014 §1, §4, §6 | **Paths.** SoC descriptions are `soc/<vendor>/<family>/<file>.yaml`. A part file extends a die file, which extends a family base, and only a part may be a board's `soc` (`abstract: true` marks the others). Board descriptions stay at `boards/<vendor>/<board>/board.yaml`, the existing layout, instead of `boards/<vendor>/<board>.yaml`. The board's `soc` key is relative to `soc/`. **Outputs.** Generated files live in the board's `generated/` directory and are committed, so a build needs no Python beyond what configuration already needs. **Tools.** The generator is `hw/gen/emb-hwgen.py` with its package in `hw/gen/emb_hwgen/`, and the schemas are `hw/schemas/{soc,board,hw}.schema.json`. **Inheritance.** A file's identity keys (`name`, `extends`, `abstract`, `doc`, `part`, `package`, `curated`, `imported_from`) are not inherited. Lists of named nodes merge by name. | `hw/gen/emb_hwgen/load.py` |
| A67 | SPEC-014 §1, §13.1, HW-002 | The schemas are JSON Schema 2020-12. The generator validates them with an in-tree implementation of the keyword subset they use (`type`, `const`, `enum`, `pattern`, `minimum`, `maximum`, `minItems`, `maxItems`, `required`, `properties`, `additionalProperties`, `items`, `oneOf`, local `$ref`), so PyYAML stays the build's only third-party Python dependency. A schema using any other keyword is refused. CI also runs the reference `jsonschema` package and requires both validators to accept and refuse the same documents. Schema errors are reported before semantic rules run. | `hw/gen/emb_hwgen/schema.py`, `hw/gen/test_hwgen.py` |
| A68 | SPEC-014 §6, §7, HW-010, HW-011 | **First increment, outputs.** The generator emits `hw_config.h`, `board_pins.c`, `regions.ld`, `board.conf` (the Kconfig.board fragment), `board.cmake` and `hw.json`, plus `board.md` and `build_report.md` for review. The PLL factors, bus dividers, flash wait states, regulator scale and over-drive come from a clock solver and are emitted as constants in `hw_config.h`. A separate `soc_clocks.c` is not emitted while one bring-up sequence serves the family. **Not yet emitted:** the system description and its outputs (`partitions.c`, `caps_init.c`, `ceilings.h`, `init_order.c`, `Kconfig.system`), `soc_devices.c` (it needs the DRV-001 device model), `embld.opts` (it arrives with the Uno's migration), the importers (HW-004, HW-012), the CTF trace metadata and `migrate` (HW-014). **First increment, rules.** Implemented: schema, unresolved references, duplicate keys and names, overlapping memory regions and peripheral blocks, flash partitions outside flash, overlapping or not on erase-sector boundaries, duplicate, out-of-range or reserved interrupt lines, pins assigned twice, unbonded on the package or given an alternate function the SoC does not offer, oscillators out of range, unreachable frequencies and bus overspeed, port-manifest mismatches, errata for unknown revisions, and board defaults that override a hardware fact. Rules that need the system description (partition constraints, ceiling users, device dependency cycles) and the `safety` refusal of uncurated nodes wait for it; uncurated descriptions are reported as warnings. **Coverage.** Only the STM32F446 descriptions and the NUCLEO-F446RE exist. The other boards keep their hand-written headers until migrated. | `hw/gen/emb_hwgen/model.py`, `hw/gen/emb_hwgen/clock.py`, `hw/gen/emb_hwgen/emit.py` |
| A69 | SPEC-014 §6, HW-001, SPEC-012 §11 | **What a generated board holds.** A board described in YAML holds only `board.yaml` and `generated/`, which also gets a `CMakeLists.txt`. `generated/board.cmake` names the SoC family's board support directory (`soc/<vendor>/<family>/`). That directory builds `emb_board` from its family board support (`board.c`, the `emb_board.h` interface) and the family's drivers in `drivers/<vendor>/`. **Where facts may live.** Register base addresses, memory regions, gates, pins and frequencies appear only in descriptions and generated files. Driver C keeps register offsets and bit layouts. HW-001's analysis is `emb-hwgen.py check`: a generated board's directory must contain nothing else, and C under `soc/` and `drivers/` must contain no hexadecimal literal of seven or more digits. **Staleness.** Configuration refuses a board whose `generated/board.cmake` input hashes no longer match its descriptions, and reconfigures when one changes. **Console message.** The clock-failure message no longer names the NUCLEO's MCO: it gives the requested frequency and asks whether the HSE input is running. | `soc/st/stm32f4/`, `drivers/st/`, `cmake/emb_config.cmake`, `hw/gen/emb_hwgen/facts.py` |
| A70 | SPEC-014 §3, §6, §12, HW-006, SPEC-012 §11 | **The ATmega328P and the Arduino Uno.** **Address spaces.** A memory region or peripheral may name its address `space` (default `main`), and overlaps are checked only within a space. The ATmega328P has `program`, `data` and `eeprom`. **Interrupts.** The interrupt controller may be `avr`: it lists every vector by name and number, `priority_bits` is required for an NVIC only, and a peripheral's line must be a listed vector. The header emits `EMB_VECTOR_<NAME>` for the port's `EMB_ISR(name)`. **Pins and flash.** An alternate function may be `fixed`, for a pin the peripheral takes over without a selection register (USART0 on PD0 and PD1); a board names such a pin without `.af<n>`. Flash geometry may be uniform pages (`page_size`) instead of a sector list. A partition may be `reserved` (Optiboot). Oscillators may have any name (`xtal`). **Outputs.** The AVR outputs are `hw_config.h`, `regions.ld` from avr-libc's avr5 script (FSF notice kept) and `embld.opts` (`-Ttext`, `-Tdata`, `--rom-limit`, the HW-006 option set, tested for agreement with the script and with `cmake/toolchains/embcc-avr.cmake`), plus `board.conf`, `board.cmake`, `CMakeLists.txt`, `hw.json` and the reports. The STM32 pin table is emitted only for that family. **Linker.** The script's text region is the app partition (32,256 bytes) instead of the toolchain's 32 KiB default, so an image that would overwrite Optiboot fails to link. Data and EEPROM come from the description. **Board support.** `soc/microchip/atmega/` and inline drivers in `drivers/microchip/include/` replace `board.c`. They are inline so that constant bases fold into single I/O instructions and the baud divisor into a constant, and all 48 images of the three AVR presets are byte-identical in `.text` and `.data`. `EMB_HW_SOC` now reads `ATmega328P` (the part name) instead of `atmega328p`; no code reads it. | `soc/microchip/atmega/`, `drivers/microchip/`, `hw/gen/emb_hwgen/templates/avr5.ld` |
| A71 | SPEC-015 §4, OBS-016, API-017 | **Crash record layouts.** The record is a little-endian byte string, never a C struct, closed by a CRC-32 (IEEE, reflected) over everything before it. **Version 1** (32-bit and native ports, 92 bytes) keeps SPEC-015's fields and order with two corrections: the fault code is 16-bit, as `emb_fault_info_t` has it, and `argument` and `api_id` are added, which API-017 requires. The layout reads: `magic "EMBC" | version | length | build_id[20] | fw_version[8] | uptime_ticks u64 | reset_reason u32 | fault_class u8 | argument u8 | code u16 | api_id u16 | cpu_id u8 | partition_id u8 | thread_index u16 | thread_generation u16 | address | pc | lr_or_ra | sp | stack_base | stack_size (u32 each) | status_reg_count u8 | gpr_count u8 | flight_event_count u16 | [registers] | [flight recorder] | crc32`. **Version 2** (pointers of 16 bits, AVR, 34 bytes) is `magic | version | length | build_id[4] | uptime_ticks u32 | reset_reason u8 | fault_class u8 | argument u8 | thread_index u8 | code u16 | api_id u16 | pc u16 | sp u16 | address u16 | crc32`. **This increment.** No registers and no flight recorder (counts 0): they need the ports' register capture and the trace rings. `lr_or_ra`, the stack bounds, the generation, the CPU and the partition are 0. **pc.** A software fault's pc is now the return address into the code that raised it (`EMB_RETURN_ADDRESS()`, GCC and Clang; 0 elsewhere), taken only where the record is enabled. On AVR the record holds the word address avr-gcc reports; a decoder doubles it for byte-addressed tools. | `kernel/fault/crash.c`, `kernel/fault/fault.c`, `include/emb/compiler.h` |
| A72 | SPEC-015 §4, OBS-019 | **Build identity.** `build_id` is SHA-1 over the git commit, a `+dirty` mark when tracked files differ from it, and the configuration hash, fixed at configure time. It is also the flash constant `emb_build_id[20]`, which `tools/crashdec` reads from the ELF to refuse another build's record. Two dirty builds of one commit and configuration share an id. **Firmware version.** `fw_version` is the new `CONFIG_EMB_FW_VERSION` (default `"0.2.0"`), zero-padded to 8 bytes. **Reset reason.** `reset_reason` is the action the kernel took: 1 reboot, 2 halt. The SoC's reset-cause register is not read; that waits for board drivers. | `kernel/CMakeLists.txt`, `kernel/Kconfig` |
| A73 | SPEC-015 §4, §9, SPEC-011 §11, ARCH-AVR-008 | **Where the record lives.** The port gives the memory its reset leaves alone: `emb_arch_retained(&size)`, plus `emb_arch_retained_sync(store)`, which is a no-op except on native. On Cortex-M and RISC-V it is 128 bytes the linker script reserves at the top of RAM, above the stack, as symbols and not a section (`__emb_retained_start` and `__emb_retained_end`): QEMU's `virt` machine re-zeroes every ELF segment on reset, `.noinit` included, but not memory outside them. On AVR it is a 34-byte `.noinit` array, which avr-libc's startup leaves alone. On native it is a buffer mirrored to `$EMB_NATIVE_CRASH_FILE` when set, the host file of SPEC-015 §9. **When it is written and read.** The kernel writes the record after the fault's trace record and before the hook and the action (FLT-001, KRN-IRQ-030), and validates it once in `emb_kernel_init()`. **API.** `emb_crash_record_get()` returns `EMB_ENOENT` without a valid record and `emb_crash_record_clear()` discards it (API IDs 145 and 146). A fault overwrites an unread record. **Reset.** New port function `emb_arch_system_reset()`: the reset `emb_arch_reset()` ends in, without the board's report. That is SYSRESETREQ on Cortex-M, the watchdog on AVR, `emb_board_system_reset()` on RISC-V (riscv32_virt: the sifive_test reset; others: none yet) and process exit on native. **AVR watchdog.** A watchdog reset leaves the watchdog running, so the AVR port now clears WDRF and stops it in `.init3`. Without that, the fault action REBOOT reset the part every 15 ms. **Configuration.** `CONFIG_EMB_CRASH_RECORD` defaults to y, but to n on the tiny profile, unlike SPEC-015 §9 and ARCH-AVR-008: its code (about 1 KiB with gcc-avr 7.3) exceeds the tiny AVR footprint gates, which sit close to their limits. A tiny build opts in, as the `avr-uno-embsim` preset does to verify the AVR record. Raising the gates instead is the owner's call. | `include/emb/crash.h`, `include/emb/arch.h`, `arch/*/`, the linker scripts |
| A74 | SPEC-015 §4, SPEC-011 §11, OBS-016 | **Registers in the crash record.** Version 1 carries the port's registers after `flight_event_count`: `status_reg_count` fault status registers, then `gpr_count` general registers, 4 bytes each. `length` is 92 plus 4 per register, and boot validation requires it to match the counts. New port function `emb_arch_crash_regs(info, regs, max, &status_count, &lr)` supplies them, for hardware faults only. On Cortex-M they are CFSR, HFSR, MMFAR and BFAR, then the stacked r0 to r3, r12, lr, pc and xPSR; the frame is skipped when the CFSR says stacking itself failed (STKERR, MSTKERR). On RISC-V they are mcause, mtval, mepc and the frame's mstatus, then ra and a0 to a7. AVR and native give none. `lr_or_ra` is the stacked lr or the frame's ra. `emb_crash_record_t` gains `lr`, `status_count`, `gpr_count` and `regs[16]`. The retained area on Cortex-M and RISC-V grows from 128 to 192 bytes, as does the native buffer. `tools/crashdec` names the registers by the ELF's machine (or `--arch`) and spells out the CFSR and HFSR bits and the mcause. | `kernel/fault/crash.c`, `arch/cortex_m/cm_port.c`, `arch/riscv/rv_port.c`, `tools/crashdec/crashdec.py` |
| A75 | SPEC-014 §3, §4, §6, HW-001 | **The emulated reference boards from their descriptions.** The MPS2 AN385 and AN386 (`soc/arm/mps2/`) and QEMU's RV32 virt (`soc/qemu/virt/rv32.yaml`) are described, and their boards build from `generated/`. **Schema changes.** A board's `oscillators` are optional, for a SoC whose clock is fixed. A console needs a tx pin only on a SoC with pin muxing (`gpio`). `test_irqs` may name one line. The interrupt controller may be `clint`, whose count is the machine interrupt numbers. **Outputs.** A RISC-V RAM-only linker template, loaded and run in RAM. The RISC-V port's Kconfig symbols come from the description: `CONFIG_EMB_RV_CLINT_BASE` from the `riscv,clint0` peripheral, spelled in hex as the hand-written file did so the configuration hash is unchanged, `CONFIG_EMB_RV_MTIME_HZ` from the `timebase` source, and `CONFIG_EMB_RV_IRQ_COUNT`. **Names.** The board support uses the generated names: `EMB_HW_CONSOLE_BASE`, `EMB_HW_FPGAIO_BASE` for the MPS2 LED, which had a literal address, and `EMB_HW_TEST_BASE` for the sifive_test device, formerly `EMB_HW_TEST_DEVICE`. **Result.** The configuration hashes are unchanged, and every image of the seven QEMU presets is identical except for the 20-byte build id. The ESP32-C3 stays hand-written until #46, which rewrites its board, is merged. | `soc/arm/mps2/`, `soc/qemu/virt/`, `hw/gen/emb_hwgen/` |
| A76 | SPEC-014 §1, §4, §6, HW-003, HW-013, ADR-051 | **Boards outside the tree.** A board may live in a project's own tree. The new CMake cache variable `EMB_BOARD_ROOT` lists directories (relative ones from the source tree), each holding the `boards/<vendor>/<board>/` layout. Configuration looks the board up in the tree and in every root, and refuses a root without `boards/` and a name found more than once. Such a board names the tree's SoC descriptions as any board does; SoC descriptions and family board support stay in the tree. **Stamps.** The generator records a file outside the tree as `@board/` and its path from the board's directory, and the staleness check resolves it there. A warning written into `hw.json` or `build_report.md` names the board the same way, while the terminal shows the real path, so the outputs are the same bytes on every machine and from every working directory (HW-013). The regeneration hint reads `--board <path to>/<board>`. Boards in the tree are stamped as before, and their outputs are unchanged. **Check.** `emb-hwgen.py check --board-root DIR` (repeatable) checks a project's boards instead of the tree's, without the tree's facts check. | `cmake/emb_config.cmake`, `hw/gen/emb_hwgen/load.py`, `hw/gen/emb_hwgen/generate.py`, `hw/gen/emb-hwgen.py` |
| A77 | SPEC-014 §8, HW-004, HW-012, ADR-051 | **The SVD importer.** `hw/import/svd.py` turns `embsvd --json` output into a SoC draft that validates against the schema. The draft covers the core (Cortex-M0 to M55), the interrupt controller with its reserved lines, and the peripherals off the private peripheral bus, with their bases, sizes, deduplicated interrupts and, from `hw/import/compat/<vendor>.yaml`, their `compatible`, GPIO port and clock gate. Memory comes from `--flash` and `--ram`. What an SVD lacks is listed as `todo` comments instead of `todo` markers in the data, so a draft still validates. An unmapped peripheral's `compatible` is `svd,<group>`, which binds no driver; SPEC-014 §8 had said `todo`. A draft is `abstract: true` and `curated: false`. **Re-import (HW-012).** `--against` prints differences and never writes a description, and `-o` refuses a file holding curated nodes. The author applies what the SVD gets right, so curated nodes are never overwritten; no merge is automated. **Variant spellings.** Armv8-M variants are `armv8m-main` and `armv8m-base`, and Armv8.1-M is `armv8.1m-main`, because a schema identifier admits no dot. **Verification.** HW-004's STM32F407 SVD is replaced by the STM32F446's, which has a curated description to compare with. The comparison agrees on every fact except where the PVD interrupt sits, and is recorded in docs/engineering/hwgen.md. The DeviceTree importer of HW-004 is step 6 of the any-board plan. | `hw/import/svd.py`, `hw/import/compat/st.yaml`, `hw/import/test_svd.py` |
| A78 | SPEC-011 §2, §3, 07 §2 (M3), ADR-051 | **Armv8-M Mainline (Cortex-M33).** The Cortex-M port gains variant `armv8m-main` (the spelling A77 fixed). The variant runs in the Secure state with TrustZone unused: no SAU configuration, no non-secure image, no secure gateway. Its EXC_RETURN values, exception frames, BASEPRI critical sections, PendSV switch and FPv5 lazy stacking are those of Armv7E-M, so the port's code does not change; the header accepts `__ARM_ARCH_8M_MAIN__`. The manifest lists the variant for zero-latency interrupts, CAS, lazy FP stacking and the cycle counter. `hw_stack_limit` stays empty: PSPLIM needs each thread's stack base in the port's control block, and is a separate step. **Reference board.** `mps2_an505` (QEMU `mps2-an505`), described from QEMU 11.1's sources, reuses the MPS2 board support: code and RAM at their Secure aliases (0x10000000, 0x38000000), the UART and FPGA I/O at theirs (0x50200000, 0x50302000), a 20 MHz processor clock that also drives SysTick, and 124 NVIC lines with test lines 120 and 121. Presets `cm33-an505`, `-release` and `-tiny` run in the QEMU CI job. Changing the manifest changes the input hash stamped in every Cortex-M board's outputs, so those outputs were regenerated, with only the hash changing. | `arch/cortex_m/arch.yaml`, `arch/cortex_m/include/emb_arch.h`, `soc/arm/mps2/an505.yaml`, `boards/arm/mps2_an505/` |
