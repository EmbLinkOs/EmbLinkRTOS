# Specification amendments recorded during M3

Corrections and implementation decisions made during M3a, where an accepted specification
is narrowed, reordered or made concrete. Each is applied in the affected document, and this
page keeps the audit trail. Numbering continues from the [M2 record](AMENDMENTS-M2.md).

**Status:** proposed with the first hardware generator increment, awaiting the project owner's review.

| A66 | SPEC-014 §1, §4, §6 | **Paths.** SoC descriptions are `soc/<vendor>/<family>/<file>.yaml`. A part file extends a die file, which extends a family base, and only a part may be a board's `soc` (`abstract: true` marks the others). Board descriptions stay at `boards/<vendor>/<board>/board.yaml`, the existing layout, instead of `boards/<vendor>/<board>.yaml`. The board's `soc` key is relative to `soc/`. **Outputs.** Generated files live in the board's `generated/` directory and are committed, so a build needs no Python beyond what configuration already needs. **Tools.** The generator is `hw/gen/emb-hwgen.py` with its package in `hw/gen/emb_hwgen/`, and the schemas are `hw/schemas/{soc,board,hw}.schema.json`. **Inheritance.** A file's identity keys (`name`, `extends`, `abstract`, `doc`, `part`, `package`, `curated`, `imported_from`) are not inherited. | A71 | SPEC-015 §4, OBS-016, API-017 | **Crash record layouts.** The record is a little-endian byte string, never a C struct, closed by a CRC-32 (IEEE, reflected) over everything before it. **Version 1** (32-bit and native ports, 92 bytes) keeps SPEC-015's fields and order with two corrections: the fault code is 16-bit, as `emb_fault_info_t` has it, and `argument` and `api_id` are added, which API-017 requires.
