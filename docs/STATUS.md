## Implemented subset

| Area | Current implementation | Evidence and limits |
|---|---|---|
| Execution and scheduling | UP fixed priority, base bitmap/FIFO scheduler, tiny thread table, scheduler lock, thread lifecycle | Common conformance cases; tiny has unique base priorities and restricted scheduling semantics |
| Waiting and time | Shared wait protocol, sleep, deadlines, cancellation, suspend overlay, ordered timeouts | Native virtual time exercises periodic and tickless modes; embedded ports currently reject tickless |
| Synchronization | Semaphores, mutexes with inheritance, ceiling, recursion and owner-death policy | Conformance and native differential bridge; inheritance and deadlock detection have a configured depth limit |
| Notifications | Per-thread bits and one semaphore-to-thread binding | Binding takes a one-bit mask; no unbind implementation; pointer lifetime remains caller responsibility |
| Objects | Caller-owned generated storage and POINTER handles | No INDEXED or TABLE handles, capability rights, partition restart or system freeze implementation |
| Native port | POSIX host-thread gate, deterministic IRQ injection, virtual time | Base/tiny development workflow; no current wall-clock, asynchronous signal stress, simulated isolated profile or Win32 backend |
| Embedded ports | ATmega328P; Cortex-M3/M4F; RV32IMAC machine mode; boards Arduino Uno, NUCLEO-F446RE, QEMU's MPS2 and RV32 virt | QEMU jobs and EmbSIM jobs (Uno, NUCLEO-F446RE) defined in CI; no real-board timing or peripheral/HIL validation recorded here |
| Configuration/build | Kconfig subset, port manifests, CMake/Ninja, layout probe, footprint tool | GCC/Clang native CI and cross-GCC QEMU jobs; ten legacy EmbCC capabilities reviewed with scoped local checks, but current RTOS compiler CI/qualification remains incomplete |
| Observability | M1 trace sink and fault reporting | CTF rings/metadata, deferred log decoder, retained crash records, debug descriptor and worst-case monitors remain planned |
| Documentation | Sphinx/MyST manuals and native tutorials, Doxygen/Breathe C API, Sphinx Needs design catalog, JSON/CSV downloads and annotation audit | Strict local HTML build, complete extracted function annotations, source-preservation and catalog-integrity checks; merged `37887c9` Pages deployment and served evidence-workflow page independently observed successful |

| Semantic model | UP scheduler/wait/mutex/notification/lifecycle scenarios, exhaustive section-level exploration and randomized walks | Scenario-scoped exploration, not a proof of all C execution, arbitrary programs, SMP or hardware protection |

## Known limits and unresolved evidence

The [EmbCC layout-marker correction](engineering/embcc-layout-marker.md), source `3578006`, supplies the portability macro; storage/assertion/kernel-archive compilation passed on eight configurations. The subsequent [Linux native integration](engineering/embcc-native-linux.md), source `df32ec2`, adds explicit experimental EmbCC-kernel/GCC-host presets and a build-time layout guard. Actual checked/release/tiny/periodic mixed builds passed all twelve CTest targets each and 11,200 seeded model comparisons in total, with zero divergences. GCC compiles the POSIX port, board, applications and harness and links the real Linux runtime; this is not an all-EmbCC host build. The latter still fails on glibc header compatibility after an explicit system-header/link experiment. Compiler CI currently checks the marker/launcher contracts and the existing matrix; the EmbCC executions are scoped local evidence.

- Hardware timing and total memory use remain to be demonstrated on the primary Cortex-M board. Map-derived kernel subtotals exclude port, board, runtime and stack costs.
- The Cortex-M base TCB figures in the port page exceed R-003 T4's target; that is a disclosed target miss, not a failed native setup.
- The [M2-01 timer correction](engineering/m2-01-timer-correction.md) addresses the reproduced seed-3 model timing gap, and the [evidence workflow](engineering/differential-evidence.md) provides automatic bundles, exact replay and bounded schedule reduction. The [bounded triage](engineering/m2-01-seed5-triage.md) leaves the historical seed-5 cancellation finding unconfirmed without its original schedule/build. Passing current campaigns does not establish the historical cause or close all of M2-01.
- AVR launch/restore uses `out SREG; pop r0; ret`; pending IRQ coherence during that tail remains a physical validation obligation (A27), not a verified atomic out/ret pair.
- Embedded fault-expectation cases that require host `fork` are skipped. A passing emulator job does not establish those misuse paths on hardware.
- The [M2-02 IRQ correction](engineering/m2-02-irq-priority.md) implements larger-is-more-urgent in the advertised kernel-aware domain: Cortex-M derives the range/encoding from board priority width and BASEPRI; native, AVR and current RV32 expose level 0 only. Invalid requests fault when checked or return an error in release before controller writes. SysTick defaults to highest kernel-aware urgency. Initial QEMU M3/M4 and F446 EmbSIM runs passed the new register/order/preemption cases; local checked/release/tiny/periodic native and experimental EmbCC-kernel/GCC-host checked builds each passed 13 CTest targets. Physical latency/jitter, raw kernel-independent vectors and generic hardware-description generation remain unqualified/unimplemented; the raw class is refused at configuration.
- Tiny uses its current base-priority table slot as `emb_thread_index()`, so reprioritization changes that diagnostic index. KRN-THR-025's stable-index target is not met across that operation. Generic fault records also leave `api_id` at zero; retained crash records and full API attribution remain incomplete.
- Base diagnostic-index allocation saturates at `0xFD`, so uniqueness is not established across repeated initialization; current init paths also lack general active-storage double-init detection. The [M2-02 review](engineering/m2-02-contract-review.md) records these source-analysis findings and proposals, without changing accepted contracts or claiming new runtime tests.
- The former ten-item EmbCC compiler backlog is implemented upstream and the RTOS layout marker is supplied. An explicit mixed Linux native strategy now executes the kernel; all-EmbCC POSIX host compatibility, AVR flash/registration macros and compiler-matrix CI/qualification remain open. Available CMSE, atomics, DWARF and embedded C++ retain their documented scope and restrictions; see the [capability review](engineering/embcc-capability-review.md) and [marker correction](engineering/embcc-layout-marker.md).
- Planned isolation must meet SPEC-010's DMA, pointer lifetime, generation and restart obligations before fault containment is claimed. CPU protection alone is insufficient.
