### Added (the device and driver model, 2026-11-09)

- SPEC-016, proposed: the device and driver model M4.1 implements. A device is a `const` instance the generator emits and the application reaches by symbol (`EMB_DEVICE(spi2)`), with a lifecycle (UNINIT, INITIALIZING, READY, SUSPENDED, FAILED) visible through the API and the debug descriptor. Devices initialize in two levels, EARLY (polled, before the kernel) and KERNEL, each in an order the generator computes from their dependencies. Every class operation is a request with a completion target (a notification, a semaphore, a work item, a bounded callback or polling); blocking calls are wrappers over it, with cancellation and timeouts defined per class. Drivers are bound to devices at generation from `drivers/bindings.yaml`, so an image contains only the drivers its devices use ([SPEC-016](docs/specs/SPEC-016-device-and-driver-model.md)).
